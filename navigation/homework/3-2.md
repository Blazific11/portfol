## Homework

### Grow the game and test an empty project

Prediction: [12, 23, 10, 7], 4 levels, 52 stars; empty project has 0 levels and 0 stars.

```python
# CODE_RUNNER: Grow the game and test an empty project
def report(level_stars):
    total_stars = 0
    for stars in level_stars:
        total_stars = total_stars + stars
    print(level_stars)
    print("Level count:", len(level_stars))
    print("Total stars:", total_stars)
    return total_stars
level_stars = [12, 18, 10]
level_stars[1] = level_stars[1] + 5
level_stars.append(7)
assert report(level_stars) == 52
assert report([]) == 0
```

**Actual output**

```text
[12, 23, 10, 7]
Level count: 4
Total stars: 52
[]
Level count: 0
Total stars: 0
```

## Tests

The main and empty cases passed. The empty test performs only traversal, avoiding an invalid second-element access. Each element represents stars for one level, in level order. With 100 levels, one list and one traversal avoid 100 variable declarations and 100 hand-edited terms in a sum. This reduces maintenance; it does not guarantee faster execution.

## Design Thinking

A maker needs to extend the game without breaking totals. The prototype replaces separate variables with a list, updates level two, and appends a new level. Testing an empty list confirmed that the counter works before any levels exist. Display labels such as Forest, Cavern, and Summit instead of asking players to understand zero-based indices.
